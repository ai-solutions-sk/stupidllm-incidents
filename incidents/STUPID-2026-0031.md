CVE-2025-48757 records that an insufficient database row-level security (RLS) policy in Lovable-generated sites let remote, unauthenticated attackers read or write arbitrary database tables. Lovable builds apps on Supabase, where RLS policies are what stop the public API key in the browser from reaching every row; apps generated before 15 April 2025 could ship without adequate policies.

A security researcher scanning apps from Lovable's public showcase found about 170 of 1,645 vulnerable, across roughly 300 endpoints, with exposed data reportedly including home addresses, personal debt amounts and API keys. Because the gap came from what the generator produced rather than from one developer's mistake, it repeated across every affected app. Lovable's response was a security scanner; secondary reports note it detects whether RLS exists rather than whether the policies are correct.

An earlier version of this record cited an unrelated article (about Moltbook) and described the flaw as inverted access-control logic; both were corrected on 2026-10-29 against the CVE record.
