A Claude Code user running v2.0.55 on macOS (via a PyCharm terminal) reported that, in a prior session, the agent had created a directory literally named `~` — the reporter calls it a glitch, with no indication of how the name arose. Later in that same session, Claude Code ran `rm -rf *` in the parent directory. Because a literal `~` entry was sitting there, the shell's glob expansion carried the deletion into the reporter's actual home directory, and it began recursing through it.

The reporter didn't quantify what was lost, only that the agent "proceeded to start wiping my home directory" and that recovering from it was "continuing to be super frustrating" at the time of filing. Their ask was narrow and specific: never run `rm -rf *` instead of naming exact directories, and treat a directory named `~` as the red flag it is — at minimum, stop and ask before either one executes. Anthropic tagged the issue `area:core`, `area:security`, `area:tools`, `bug`, and `platform:macos`, then closed it as "not planned." No fix was linked in the report, and the combination that caused it — Claude Code creating a stray `~` directory, then later deleting into it via an unescaped glob — remains possible today.
