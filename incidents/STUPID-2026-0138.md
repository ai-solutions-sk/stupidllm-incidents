A Cline user (csimonb), running VS Code extension v4.1.21 with the Claude
Code provider (Claude Sonnet 5, Claude Code CLI 2.1.263), reported that any
tool call needing Claude Code's permission — terminal commands, MCP tool
calls, and reads or writes outside the workspace — is refused with no
approval prompt. The issue gives five numbered reproduction steps: create a
workspace folder and an outside folder, ask the agent to read/write the
outside folder and run a shell command (both refused with no prompt), add
permission rules to the project's `.claude/settings.json` (no effect), then
move the identical rules to the user-level `~/.claude/settings.json`, where
they work. The reporter traced the cause to Claude Code's workspace-trust
gate: the CLI logs "Ignoring 2 permissions.allow entries from
.claude/settings.json: this workspace has not been trusted" when a folder
hasn't been trusted, but Cline does not surface that message anywhere in its
UI, so the user just sees tool calls fail for no stated reason. A Cline
contributor (Dante-dan) confirmed the trust-gate finding while cautioning it
doesn't rule out a separate permission-merge issue, and proposed exposing
scoped launch-time permissions and documenting the trust requirement. The
issue remains open with no fix merged as of this incident's publication.
