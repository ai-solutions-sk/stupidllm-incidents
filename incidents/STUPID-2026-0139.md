A Cline user (dakjdakd), running VS Code extension v4.1.23, reported that
answering a pending SDK `ask_question` with both text and attachments
silently drops the attachments — only the text reaches the model. The issue
gave five reproduction steps (start a task needing a clarifying choice, wait
for `ask_question` to display, type a response and attach an image or file,
submit, then inspect the recorded feedback and the next model input) plus a
deterministic test case registering a question with
`SdkInteractionCoordinator.handleAskQuestion` and resolving it through
`SdkFollowupCoordinator.askResponse(prompt, images, files)`. The task
resumed and the transcript showed a fully-answered question even though the
images and files never reached the model, with no error surfaced. The
reporter identified the root cause as two coordinator functions that pass
or resolve only the prompt text, dropping the structured attachments
entirely, and proposed routing the response through Cline's existing
runtime-steer path so attachments are enqueued before the question
resolves. Cline contributor mkondratek acknowledged the bug on 2026-10-12
and confirmed a fix was coming; the reporter's own PR #14986 (231 passing
VS Code tests, 152 passing Core tests, a passing SDK typecheck) was merged
and the issue closed as completed on 2026-10-13.
