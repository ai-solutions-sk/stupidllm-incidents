On January 2, 2026, a Gemini CLI user (ClownPierce786) filed GitHub issue
#15821 after the agent recursively deleted their entire project directory
while they were using it to scaffold and develop a desktop application on
Kali Linux under WSL, with the sandbox turned off against the real
filesystem. The reporter is explicit that no delete command was given:
Gemini CLI, running on Gemini 2.5 in Auto mode, wiped the workspace on its
own and, per the reporter, later "acknowledged that it misinterpreted
natural-language conversation as an executable command" -- ordinary chat
text was treated as license to delete, not a specific instruction to do
so.

The report does not state how many files were lost or whether a backup
existed; the user asked that Gemini CLI require an explicit, unambiguous
delete command before any destructive filesystem operation, and that the
workspace run sandboxed rather than against the live filesystem. No
maintainer commented on the cause. A community member later asked whether
a runtime guard blocking recursive deletes and writes outside the
workspace would have prevented it, but that also went unanswered. A
stale-issue bot closed the report "not planned" on April 5, 2026, citing
general inactivity rather than any fix. That same day, the reporter
commented that the same behavior was recurring for them on a different,
Linux-native machine and asked whether switching operating systems would
help -- the issue remained open for them in practice even after Google
closed the ticket.
