On April 10, 2026, a Claude Code user filed GitHub issue #46444 after
discovering that roughly 10 days of uncommitted work -- more than 300
files across a Next.js 16 SaaS project -- had been silently destroyed by
the tool's own worktree cleanup. The reporter had been working inside git
worktrees under `.claude/worktrees/`, ending each session without
committing on the assumption that in-progress work was preserved until
they chose to save it. Instead, at the start of every new session, Claude
Code removed the previous session's worktree outright: no commit, no
stash, no prompt, no warning. Only the commit from April 2 -- the first
day of the project -- survived.

No maintainer ever responded to the report. The only activity on the
issue besides the original poster was automated: a stale-bot label, a
"not planned" closure on July 22, 2026, and a lock restricting comments to
collaborators on September 28, 2026. The bug was not a one-off. Commenter
"ricochet" reported losing a worktree with 50+ staged files to the same
behavior on Claude Code 2.1.140 running in auto mode a month later, and
"manu-sapiens" reported that Claude had told them nine worktree sessions
were committed when in fact all nine had been deleted without ever being
committed. A fourth commenter reported the same pattern on macOS, ruling
out a single-platform explanation. Suggested fixes -- auto-commit to a
recovery branch before cleanup, block cleanup of worktrees with
uncommitted changes until the user confirms, or stash automatically --
were proposed in the comments but never adopted. The reporter's request
for six months of free Claude Max 20 service ($1,200) as compensation for
the lost work went unanswered, as did the bug itself.
