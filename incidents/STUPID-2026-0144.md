Cline CLI user anachaudhari filed GitHub issue #14827 on October 4, 2026,
describing an intermittent bug in Cline 3.0.68 on Windows 11: when running
against a local llama.cpp server through Cline's openai-compatible
provider, the model's `run_commands` tool call sometimes arrives with
empty or fragmentary arguments while other tool calls in the same session
(e.g. `editor`) arrive intact.

In the worst documented run, the malformed call repeated seven times —
two empty argument lists and five identical fragments — before Cline's own
loop detector intervened ("Detected 5 consecutive identical calls to
run_commands; stopping to avoid a loop"), the yolo-mode three-mistake
limit was reached, and the run terminated with `run_aborted` /
`external_abort` and the message "aborted by another client," even though
no other client was involved. In a second run the first `run_commands`
call was also empty, but that run recovered and completed. The reporter
instrumented a logging proxy that captured 16 requests and 2,333 streamed
tool-call argument deltas; every captured stream reassembled into valid
JSON, so the corruption was never caught in the act, and it did not occur
at all in 3 proxied runs (versus 3 of 4 direct runs).

Cline maintainer mkondratek responded on October 7, finding no
chunk-boundary handling bug on Cline's side, and noted that llama.cpp
returning a `finish_reason: "length"` stop (hitting the context/output
limit) can pass through a repair step that converts a cut-off tool call
into an empty command list — pointing at PR #14909 as a fix that would at
least stop a cut-off call from executing rather than running on partial
arguments. After repeated requests for the specific failing request's
finish_reason and llama-server slot diagnostics went unanswered, the
maintainer reviewed about 2 million production responses over two weeks on
October 19, found 372 that hit the output-token limit but none mid-tool-call
and none with an empty command list, and concluded the issue is probably
specific to this reporter's local openai-compatible setup rather than a
general Cline defect. PR #14909 remains parked rather than merged; a
second PR, #15089, is intended to turn a bare empty command list into a
visible tool error on any future occurrence rather than a silent one. As
of this writing the issue remains open with no confirmed root cause.
