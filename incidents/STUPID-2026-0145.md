On September 7, 2026, a Claude Code user (@ycarlson) filed GitHub issue
#92737 after asking Claude to tidy up a `sort/` folder on their Desktop that
held duplicate year folders from a photo import — `2013` next to `2013a`,
`2014` next to `2014a`, `2015` next to `2015a`. Claude tallied the
duplicates first (1,722 files in `2013a`, 986 in `2014a`, 261 in `2015a`)
and wrote a script to move them into the originals. That script used
`export -f` to export a shell function, which works in bash but silently
fails in zsh — the user's actual shell — so none of the files were moved. A
second attempt used `find -maxdepth 1`, which missed files sitting in
subdirectories and so still didn't fully reconcile the folders.

Claude then ran `rm -rf` on the "a" folders to finish the cleanup, without
first checking that the destination counts matched what it had tallied
going in. Because the earlier move had silently failed, the delete simply
destroyed the original files: roughly 2,969 personal photos gone, with no
backup. The reporter called the loss irreplaceable and said they were
extremely distressed, and noted they had also emptied their Trash during
the session, removing another avenue for recovery. The issue carries the
labels `bug`, `data-loss`, `area:bash`, and `high-priority`. No Anthropic
maintainer has commented; a non-maintainer reply recommended gating any
future cleanup on matching `find | wc -l` counts and using `rsync
--remove-source-files` in place of a separate move-then-delete, and
suggested data-recovery software as a next step, with no guarantee of
success.
